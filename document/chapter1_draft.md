## 3. インフォグラフィック作品(ヒートマップ)の構想

### 3.1 形(推奨案)
- **三角形(三項図)**: 頂点を「デザイン」「エンタメ」「アート」とし、三角形の内側の位置で「3要素の混ざり具合」を表す。
- **ヒートマップ**: 頂点に近いほどその要素の色が濃く(熱く)なる。中央は3つが混ざる領域で、色が溶け合う。
- 3要素は「どれか1つ」ではなく「割合」で語るため、軸が3本ある三項図が自然。
- 各具体例は **(デザイン, エンタメ, アート)の割合**(合計1)で指定する。例: (0.2, 0.3, 0.5)。

### 3.2 動き(案)
- 表示: 頂点から色が広がって三角形が満たされる(マスクで出現)。
- 具体例の切り替え: マーカーが前の位置から次の位置へなめらかに移動し、近くの頂点のラベルが強調される。
- 案2のトーン(HUD・トラッキング枠・水色)に合わせ、マーカーはブロブ追跡の枠として描く。
- 軽量モード(Q キー)では、色のにじみや常時アニメーションを止める。

### 3.3 境界線スライド(スライド7)の構想
スライド6のヒートマップをそのまま使い、その上に「どこからがデザイン / エンタメ / アートか」の境界線を引く。

**話す内容の骨子(案)**
| ステップ | 見せるもの | 話す内容 |
|---|---|---|
| 1 | 一般的に思われている境界線 | 世間の多くはこう分けているだろう、という線。(内容は発表者が決める: 例えば「アート」の領域が小さく角にだけある、など) |
| 2 | アートを突き詰めている人の境界線(という想像) | 突き詰めている人なら、こう引くのではないか。1の線から形が変わる |
| 3 | 自分が引いている境界線 | 自分はこう引いている。ここが話の着地点で、他の2本より強く表示する |

- 2は発表者の**想像・偏見**であって事実ではない。index の「ここからは偏見になります」の流れに合わせ、断定せず「〜ではないか」と話す前提で文言を作る。
- **確定**: 3本の線は同じ三角形の上に**重ねて残す**。スライドを進めるたびに、線がアニメーションで1本ずつ増えて重なっていき、最終的に3本が重なった状態で終わる。
- 重ねた状態でも見分けられるよう、新しく足した線をいちばん太く・明るく描き、前の線は少し細く・薄くして残す(案)。

**表現**
- **確定**: 境界線は**曲線**で描く。
- 各境界線は、三角形の中を通って領域を分ける曲線(1本、または頂点ごとの複数本)として、制御点(ベジェ曲線の点)で持つ。後から線の形を調整しやすくする。
- 線は端から描かれるアニメーションで現れる。次のステップでは、前の線を残したまま、新しい線が重なって加わる(前の線は変形させない)。
- 線の近くには短いラベル(「一般的」「突き詰めている人」「自分」)を付ける。

**線の位置の決め方(進め方)**
1. ヒートマップ(三角形)を先に実装する。
2. 画面のスクリーンショットを発表者が撮り、その上に3本の線の引き方を示してもらう。
3. その線をなぞって制御点の座標にし、実装に反映する。

**未確定(この節に関するもの)**: 3本の線の具体的な形(ヒートマップ完成後にスクリーンショットで指定)/ ステップごとの説明文 / 「アートを突き詰めている人」の想像の根拠をどう話すか

### 3.4 別案(採用しない場合の比較)
- 2次元の座標軸(例: 縦=誰のため、横=評価基準)に点を置く。2軸で単純だが、3要素の「混ざり」は表しにくい。

## 4. 具体例スライドの仕様案

- 1スライド = 1具体例。入力は次の項目:

| 項目 | 内容 |
|---|---|
| 名前 | 作品・事例の名前 |
| 一言説明 | 何であるか(1行) |
| 割合 | (デザイン, エンタメ, アート)。合計1 |
| 理由 | なぜその位置か(1〜2行) |
| 画像(任意) | 使う場合は `public/` に置き、出典を明記 |

- **データ駆動にする案(推奨)**: 具体例を `src/slides/examples.js` のような1つの配列で管理し、スライドを自動生成する。追加は配列に1件足すだけで済む。共同作業で例を増やすのに向く。
- 発表時間の目安: 1例あたり約40〜60秒。例の数 × 時間で、chapter1 全体の長さが決まる。
